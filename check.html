The other two tabs only know the domains that were in the list when the monitor last scanned. This one contacts whatever you type, live. Same measurement: TLS version, the key-exchange group it negotiates, and the certificate signature.

Results are cached for one hour, and each address is limited to 12 scans every five minutes, so a repeat scan comes back instantly.

Nothing you type is stored against you. The monitor records the domain and the measurement only, never the address that asked.

A result describes one connection at one moment. The same domain can answer differently by time, by the location the scan runs from, by IPv4 or IPv6, by hostname (apex or www), and by which CDN edge happens to serve it.

About this view

The other two tabs are a scan the monitor ran earlier, so they only know the domains that were on the list at the time. This one runs the handshake when you ask for it, against any domain, and reports the same things: the TLS version, the key-exchange group and the certificate signature.

The handshake runs on the monitor's own machine rather than in your browser, so the result does not depend on which browser you happen to be using. That is also why it is a scan from one place: a CDN may route the monitor to a different edge than it routes you to.

Because anyone can type a domain in, the service only accepts names that resolve to a public address; it will not connect to a private or internal one. It does one TLS handshake and nothing else, so it never fetches the page, follows a link or logs in anywhere. The addresses behind the rate limit are held in memory only and never written down.

A domain you scan that is not in the dataset yet is noted as a candidate for the next full scan. Nothing you type here changes the published numbers. Built for the NSERC Summer 2026 research project by E. Deveci, supervised by Prof. Samer Lahoud, Faculty of Computer Science, Dalhousie University.
